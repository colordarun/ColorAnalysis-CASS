## 1. 구글 시트 만들기

1. `sheet/K-Color_시트서식.xlsx` 를 구글 드라이브에 업로드합니다.
2. 업로드한 파일을 **더블클릭 → 구글 스프레드시트로 열기**.
3. 메뉴 **파일 → Google Sheets로 저장**. 이때 만들어진 스프레드시트가 실제로 쓸 파일입니다.
   (`.xlsx` 원본은 지워도 됩니다.)
4. 탭이 `consultants` · `records` · `rules` 세 개인지 확인합니다.

### consultants 탭 — 코드 명부

| 열 | 내용 |
|---|---|
| 코드 | 접두사 `AD-` / `ED-` / `CS-` 로 시작. 뒤는 자유 (`AD-0001`, `CS-2608KR-001`, `ED-2701-CN-002`) |
| 역할 | **Admin / Educator / Consultant** 셋 중 하나. 대소문자는 가리지 않습니다 |
| 이름 · 소속 | 관리용 |
| 발급일 · 만료일 | 만료일이 지나면 로그인 차단 |
| 활성여부 | `Y` 여야 통과. 요금이 밀리면 다른 값으로 바꾸면 즉시 잠깁니다 |
| 최근접속 · 누적 진단수 | 앱이 자동으로 채웁니다 |

서식에 예시 3줄이 들어 있습니다. **운영 전에 지우고 실제 코드를 발급하세요.**
> **코드 표기는 유연합니다.** 앱은 대소문자·하이픈·띄어쓰기를 무시하고 비교합니다.
> 시트에 `AD-0002` 라고 적혀 있으면 `ad0002` · `Ad-0002` · `AD 0002` 로 입력해도 모두 통과합니다.
> `CS-2608KR-001` 처럼 지역·연도를 넣은 형식도 그대로 쓰시면 됩니다.
> 앞 두 글자만 `AD` / `ED` / `CS` 중 하나면 됩니다.


### records 탭

앱이 자동으로 채웁니다. 32개 열이고 예시 1줄이 들어 있으니 지우세요.

### rules 탭

규칙을 바꿀 때 기록을 남기는 용도입니다. 앱 동작에는 영향이 없습니다.

## 2. Apps Script 붙이기

1. 위에서 만든 스프레드시트에서 **확장 프로그램 → Apps Script**.
2. 기본으로 열려 있는 `Code.gs` 내용을 모두 지우고,
   이 저장소의 `apps-script/Code.gs` 를 통째로 붙여넣습니다.
3. 저장(Ctrl+S).
4. 함수 목록에서 **`setup`** 을 고르고 **실행**.
   - 처음 실행하면 권한 요청이 뜹니다. 계정 선택 → 고급 → *(안전하지 않은 페이지로 이동)* → 허용.
   - "설정 완료" 알림이 뜨면 됩니다.
5. 오른쪽 위 **배포 → 새 배포**.
   - 유형: **웹 앱**
   - 설명: 아무거나 (`v1`)
   - **실행 계정: 나**
   - **액세스 권한이 있는 사용자: 모든 사용자**
   - 배포를 누르면 `https://script.google.com/macros/s/……/exec` 주소가 나옵니다. **복사해 두세요.**

> **주의** — 코드를 고칠 때마다 **새 배포**를 만들어야 반영됩니다.
> "배포 관리"에서 기존 배포를 수정(연필 아이콘 → 버전: 새 버전)해도 됩니다. 이러면 URL 이 유지됩니다.

### 코드 발급하는 법

방법 A — `consultants` 탭에 직접 한 줄 추가 (가장 간단)
방법 B — Apps Script 에서 `issueCode` 함수의 위쪽 네 줄(role·name·org·months)을 고치고 실행. role 은 `Admin` / `Educator` / `Consultant` 중 하나

## 4. GitHub 에 올리기

### 저장소 만들기

1. GitHub 에서 **New repository**.
2. Repository name 에 **`ColorAnalysis-CASS`** 를 입력합니다. 로컬 폴더명과 같아야 헷갈리지 않습니다.
3. **Public** 을 선택합니다 — Pages 무료 호스팅이 Public 에서만 됩니다.
4. `Add a README file` · `.gitignore` · `license` 는 **모두 체크 해제**하세요. 이미 폴더에 있습니다.
5. **Create repository**.

### 올리기

이 폴더(`C:\Users\유잰\OneDrive\문서\GitHub\ColorAnalysis-CASS`)에서 터미널을 열고,

```bash
git init
git add .
git commit -m "ColorAnalysis-CASS 최초 커밋"
git branch -M main
git remote add origin https://github.com/<계정명>/ColorAnalysis-CASS.git
git push -u origin main
```

### GitHub Desktop 으로 하는 법 (권장)

이 폴더에는 이미 `.git` 이 만들어져 있습니다. 그래서 **Add local repository** 로 붙이면 됩니다.

1. GitHub Desktop 을 열고 왼쪽 위 **File → Add local repository…**
2. **Choose…** 를 눌러 `C:\Users\유잰\OneDrive\문서\GitHub\ColorAnalysis-CASS` 선택 → **Add repository**
   - "This directory does not appear to be a Git repository" 가 뜨면 폴더를 잘못 고른 것입니다. 위 경로가 맞는지 확인하세요.
3. 상단 메뉴 **Repository → Repository settings…** → **Remote** 탭
   - **Primary remote repository (origin)** 칸의 주소를 확인합니다.
   - `https://github.com/<계정명>/ColorAnalysis-CASS.git` 처럼 `<계정명>` 이 그대로 있으면 **잘못된 주소**입니다.
     실제 계정명으로 바꾸고 **Save** 하세요. 예) `https://github.com/colordarun/ColorAnalysis-CASS.git`
   - GitHub 에 저장소를 아직 안 만들었다면, 이 칸을 비우고 저장한 뒤 상단의 **Publish repository** 를 누르면
     GitHub Desktop 이 저장소까지 만들어 줍니다. 이때 **Keep this code private 체크를 해제**하세요.
4. 왼쪽 **Changes** 목록에 바뀐 파일이 보입니다.
   아래 **Summary** 칸에 설명을 적고 (예: `앱 갱신`) **Commit to main**.
5. 상단의 **Push origin** (또는 **Publish branch**) 클릭.

앞으로는 4 → 5 만 반복하시면 됩니다.

> **중첩 폴더 주의** — `ColorAnalysis-CASS` 안에 또 `ColorAnalysis-CASS` 폴더가 생겼다면
> GitHub Desktop 에서 실수로 저장소를 두 번 만든 것입니다. 안쪽 폴더는 지우셔야 합니다.
> 그대로 두면 git 이 그 폴더를 다른 저장소로 취급해서 파일이 올라가지 않습니다.

> **OneDrive 안에 있습니다** — 동기화 중에 커밋하면 드물게 충돌이 납니다.
> 커밋·푸시 직전에 OneDrive 동기화가 끝났는지(트레이 아이콘이 초록 체크) 확인하시면 안전합니다.

## 5. 알아두실 점

**API_URL 이 공개됩니다.** 저장소가 Public 이면 `index.html` 안의 Apps Script 주소도 보입니다.
주소만으로는 시트를 볼 수 없고, 유효한 코드가 있어야 기록이 저장됩니다. 다만 주소를 아는 사람이
아무 값이나 보내볼 수는 있으므로, 이상 요청이 잦으면 **새 배포를 만들어 URL 을 바꾸고** `index.html` 을
갱신하면 됩니다.

**코드를 바꾸면 다시 push 해야 합니다.** GitHub Pages 는 저장소 내용을 그대로 보여주므로,
로컬에서 고친 뒤 commit → push 해야 반영됩니다. 반영까지 보통 1~2분 걸립니다.

**브라우저 캐시.** 갱신했는데 옛 화면이 보이면 Ctrl+F5 로 새로고침하세요.

**오프라인.** 색 데이터는 앱에 들어 있어 인터넷 없이도 보입니다. 다만 코드 확인과 기록 저장,
그리고 PNG 저장(html2canvas 를 CDN 에서 불러옵니다)에는 인터넷이 필요합니다.
인터넷이 끊긴 현장에서는 **인쇄하기**로 PDF 저장을 쓰시면 됩니다 — 이건 외부 라이브러리 없이 동작합니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 코드 입력 후 "확인 실패 — NETWORK" | API_URL 오타 / 배포 액세스가 "모든 사용자" 인지 |
| 항상 데모 모드로 통과됨 | `API_URL` 이 빈 문자열인지 |
| 기록이 안 쌓임 | Apps Script 에서 새 배포를 만들었는지 · `records` 탭 이름이 정확한지 |
| PNG 저장 실패 | 화면에 뜬 사유 확인. 인터넷/CDN 문제면 「인쇄하기」로 대체 |
| Pages 가 404 | Settings → Pages 에서 branch 가 main / root 인지 · push 가 끝났는지 |
