# K-Color 퍼스널컬러 컨설턴트 앱 · 설계 문서 v10

작성일 2026-08-01 (v10 개정) · 색다른컬러연구소
대상 파일 `kcolor_data.json` (776색) + `K-color DB v5.xlsx` → **실사용 606색**

---

## 0. 결론 먼저 — 가능한가

가능합니다. 요청하신 5가지 모두 웹앱 하나로 구현됩니다.

| 요청 | 가능 여부 | 방식 |
|---|---|---|
| L\*a\*b\* 12개 값 입력 → 자동 계산 | 가능 | 평균·델타·ΔE\*ab 실시간 계산 (2장 [1-1]) |
| 베스트 오브 베스트 1색 + 나머지 | 가능 | ★ 지정 방식 (2장 [4]) |
| BOB 기준 TPO 배색 3종 | 가능 | 5색 배색 · 유사색상 2종 + 반대색상 1종 (2-2장) |
| 결과 카드 만들 때 시트 자동 저장 | 가능 | 화면 전환과 동시에 Apps Script 전송 |
| PNG를 진단자에게 이메일 발송 | 가능 | Apps Script `MailApp` — 단 발송 한도 확인 필요 (2-3장) |
| 776색을 색상·명도·채도로 필터 | 가능 | 원본 데이터에 `hue`/`value`/`chroma`가 이미 들어 있음 |
| 12유형별 색 필터 | 가능 | 규칙 기반 자동 배정으로 `types` 필드를 새로 생성 (아래 3장) |
| 유형 필터 후 속성 재필터 (교집합) | 가능 | 모든 조건을 AND로 결합. 조건이 모순이면 "해당 없음" 표시 |
| 4시즌 → 3유형 → 스와치 단계 진행 | 가능 | 화면 3·4·5로 분리 |
| 결과 1장 + PNG 저장 + 링크 공유 | 가능 | PNG는 html2canvas, 링크는 Apps Script가 발급 |

한 가지 짚어둘 점 — **원본 데이터에 퍼스널컬러 유형 정보가 없습니다.** 색상·명도·채도·톤은 있지만 "이 색은 봄 라이트"라는 정보는 어디에도 없습니다. 그래서 3장의 자동 배정 규칙을 새로 만들었습니다. 이 규칙은 제 판단이 들어간 초안이므로 검토가 필요합니다.

## 1. 앱 전체 구조

```
                    ┌──────────────────────┐
                    │  GitHub Pages (정적) │  ← 앱 본체. HTML/JS/색 데이터
                    └──────────┬───────────┘
                               │ HTTPS
                    ┌──────────▼───────────┐
                    │ Apps Script 웹앱     │  ← 코드 검증 · 기록 저장 · 링크 발급
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │  구글 스프레드시트   │  consultants / records / rules
                    └──────────────────────┘
```

GitHub Pages는 정적 호스팅이라 서버가 없습니다. 컨설턴트 코드를 앱 안에 넣으면 브라우저 개발자도구로 그대로 보입니다. 유료 서비스라면 이건 곤란합니다. 그래서 코드 검증과 시트 저장을 모두 Apps Script 웹앱 한 곳에서 처리합니다. 무료이고 구글 계정만 있으면 됩니다.

### 스프레드시트 3개 탭

| 탭 | 열 | 용도 |
|---|---|---|
| `consultants` | 코드, **역할**(관리자/에듀케이터/컨설턴트), 이름, 소속, 발급일, 만료일, 활성여부, 최근접속 | 코드 검증 · 권한 판별 |
| `records` | 타임스탬프, 컨설턴트코드, 이름, 이메일, 생년월일, 성별, 연락처, 인종, 직업, 진단일, 피부명도, 모발색, 눈동자색, L\*평균, 턱 Lab, 볼 Lab, ΔL\*, Δa\*, Δb\*, Δab, ΔE\*ab, 시즌, 유형, 베스트오브베스트, 베스트컬러 12색, 메모, 동의여부, 결과ID | 진단 기록 누적 |
| `rules` | 항목, 값, 수정자, 수정일 | 웜쿨지수·톤 경계 등 규칙 변경 이력 |

### 요금 부과와 코드 관리

`consultants` 탭에 만료일을 두고 Apps Script가 검증할 때 함께 확인합니다. 월 결제가 밀리면 활성여부를 `N`으로 바꾸면 그 즉시 앱이 잠깁니다. 결제는 앱과 분리해 별도로 받는 편이 단순합니다.

## 2. 화면 흐름

```
[0] 컨설턴트 코드 입력
      │  코드 검증 통과
      ▼
[1] 진단자 개인정보 입력  ── 이름/생년월일/성별/연락처/진단일
      │                      피부·모발·눈동자 / 메모 / 동의
      ▼
[2] 4시즌 선택            ── 봄 · 여름 · 가을 · 겨울
      │                      각 카드에 시즌 대표 색 띠 표시
      ▼
[3] 3유형 선택            ── 선택한 시즌의 3유형만 표시
      │                      각 카드에 대표 7색 미리보기 + 색 수
      ▼
[4] 컬러 스와치 + 필터    ── 유형 색 전체가 촤라락 표시
      │                      색상/명도/채도/톤 필터로 교집합 탐색
      │                      더블클릭으로 베스트컬러 12색 담기
      ▼
[5] 유형 설명 + 이미지    ── 특성 수치 자동 계산 + 설명 텍스트 편집
      │                      이미지 슬롯 3개 (추후 업로드)
      ▼
[6] 결과 카드             ── 진단자 정보 + 유형 + 베스트컬러 한 장
                             PNG 저장 / 공유 링크 / 시트 저장
```

상단에 스텝 인디케이터를 두어 언제든 이전 단계로 되돌아갈 수 있습니다. 앞 단계로는 되돌아가도 입력값이 유지됩니다.

### 각 화면 구성요소

**[0] 코드 입력**
코드 입력창 1개, 확인 버튼. 코드 종류에 따라 사용 범위가 달라집니다.

| 코드 종류 | 예시 접두 | 사용 범위 |
|---|---|---|
| 관리자 코드 | `KA-` | 진단 · 교육 · 관리자 모드 전부 |
| 에듀케이터 코드 | `KE-` | 교육 모드만 |
| 컨설턴트 코드 | `KC-` | 진단 모드만 |

권한이 없는 모드 버튼은 비활성 상태로 표시됩니다. 에듀케이터 코드로 로그인하면 진단 화면을 거치지 않고 바로 교육 모드로 들어갑니다. 실패 시 사유를 표시하고(코드 없음 / 만료 / 비활성), 성공하면 권한이 담긴 세션 토큰을 브라우저에 보관해 재입력을 줄입니다.

접두사 방식은 와이어프레임 데모용입니다. 실제로는 시트 `consultants` 탭에 `역할` 열을 두고 Apps Script가 판별하므로, 코드 형식은 자유롭게 정하셔도 됩니다.

**[1] 진단자 정보**
필수는 이름과 개인정보 동의 두 가지. 나머지는 선택입니다. 4개 구획으로 나뉩니다.

| 구획 | 항목 |
|---|---|
| 기본 정보 | 이름\* · 이메일 · 생년월일 · 성별 · 연락처 · 인종 · 직업 · 진단일 |
| 피부 명도 | 기준 이미지 + V8(fair) / V7(light) / V6(medium) / V4(rich) / V3(deep) / 기타 직접입력 |
| 피부 측색값 | 4부위 × L\*a\*b\* = 12개 값 → 자동 계산 |
| 모발·눈동자 | 모발: 블론드·갈색·흑갈색·검정·염색·기타 / 눈동자: 파랑·초록·검정·갈색·기타 |

인종은 대륙 기준 6개(동아시아계 / 동남아시아계 / 중앙·서아시아계 / 유럽계 / 아프리카계 / 라틴아메리카계)에 혼혈·기타 직접입력을 더했습니다. 민감한 항목이라 필수로 두지 않았습니다.

컨설턴트 메모 안내문은 "선호이미지, 진단 목적, 피부색 특징, 드레이핑 반응, 요청사항 등"으로 바꿨습니다.

**[1-1] L\*a\*b\* 자동 계산**

턱라인 왼쪽·오른쪽, 볼 왼쪽·오른쪽 4부위의 L\*a\*b\*를 넣으면 아래가 자동으로 나옵니다.

화면에는 **일반인이 바로 이해할 수 있는 4가지만** 큰 숫자로 표시합니다. 어려운 기호는 화면에서 감춥니다.

| 화면 표기 | 실제 계산 | 읽는 법 |
|---|---|---|
| 피부색 밝기 | 전체 L\* 평균 (4부위) | 0에 가까울수록 어둡고 100에 가까울수록 밝음 |
| 부위별 피부 밝기 차 | ΔL\* = 볼 평균 L\* − 턱 평균 L\* | 볼이 턱보다 밝으면 +, 어두우면 − |
| 홍조 강도 | Δa\* = 볼 평균 a\* − 턱 평균 a\* | 값이 클수록 볼의 붉은 기가 강함 |
| 피부 균일도 | ΔE\*ab = √(ΔL\*² + Δa\*² + Δb\*²) | 값이 작을수록 부위별 색이 고름 |

「상세 수치 보기」를 누르면 턱·볼 각 평균 L\*a\*b\*, Δb\*, Δab가 펼쳐집니다. 컨설턴트가 필요할 때만 보는 영역이고, 진단자에게 보여줄 화면에서는 접힌 상태가 기본입니다.

원시값(턱·볼 평균, Δb\*, Δab)은 화면에 감춰도 시트에는 그대로 저장됩니다. 나중에 데이터가 쌓였을 때 다시 분석할 수 있어야 하기 때문입니다.

12개 값 중 하나라도 비면 계산하지 않고 안내문만 표시합니다. 조명·기기·측정 각도에 따라 값이 크게 달라지므로 앱은 수치만 제시하고 해석은 하지 않습니다.

**[2] 시즌 선택**
카드 4장. 각 카드 상단에 그 시즌 12색 띠를 깔아 시각적으로 구분됩니다. 하단에 소속 3유형 이름을 미리 보여줍니다.

**[3] 유형 선택**
카드 3장. 대표 7색 미니 스와치, 유형 설명 한 줄, 해당 색 개수.

**[4] 팔레트 (핵심 화면)**
필터 4줄이 위에 붙고 아래에 스와치 그리드가 깔립니다.

| 필터 축 | 항목 |
|---|---|
| 색상 계열 | 빨강 주황 노랑 초록 파랑 보라 자주 무채색 계열 (해당 유형에 있는 것만 표시) · 진단 모드에서는 색상군을 숨김 |
| 명도 | V8+ 매우 밝음 / V7 밝음 / V5~6 중간 / V4 어두움 / V3− 매우 어두움 |
| 채도 | 고채도 C8↑ / 중채도 C4–7.5 / 저채도 C0.5–3.5 / 무채색 C0 |
| 톤 | 선명한 밝은 기본 연한 흐린 탁한 진한 어두운 흰 아주밝은회 밝은회 회 어두운회 검은 |

같은 축 안에서는 OR, 축과 축 사이는 AND입니다. 예를 들어 "여름 뮤트 ∩ 보라 ∩ 중명도 ∩ 저채도"를 걸면 6색이 남습니다. 모순되는 조건(여름 뮤트 ∩ 선명한 톤)은 0색이 되고 "해당 없음" 안내가 뜹니다.

스와치를 한 번 누르면 오른쪽에 상세 패널(K-Color 번호, 먼셀 표기, L\*a\*b\*, RGB, CMYK, NCS, Pantone, 톤, 웜쿨지수)이 열리고, 더블클릭하면 베스트컬러로 담깁니다. 최대 12색.

**베스트 오브 베스트 (BOB)** — 담긴 색의 왼쪽 위에 ★ 버튼이 생깁니다. 이 중 1색만 ★로 지정할 수 있고, 지정된 색은 금색 테두리로 구분됩니다. 첫 번째로 담은 색이 자동으로 ★가 되고 언제든 바꿀 수 있습니다. BOB을 빼면 남은 베스트컬러 중 첫 색으로 자동 재지정됩니다.

**[5] 유형 설명 + 배색 제안**
위에서부터 BOB 강조 박스 → BEST COLOR 스와치 → TYPE PALETTE 띠 → TPO 활용 배색 → 유형 특성·설명 텍스트·이미지 슬롯 순입니다. 설명 문구와 스타일링 제안은 편집할 수 있습니다. 이미지는 `assets/types/<유형코드>/1.jpg` 규칙으로 넣으면 자동으로 잡힙니다.

**[6] 결과 카드**
한 장에 진단자 정보 / 유형명·설명 / BEST OF BEST / BEST COLOR 12색 / TYPE PALETTE 띠 / TPO 배색 3종 / 스타일링 / 진단일이 모두 들어갑니다. 이 영역 전체가 PNG로 저장·발송됩니다.

## 2-1. TYPE PALETTE 구성

유형 팔레트 24색은 **본인 유형 70% + 같은 시즌의 나머지 두 유형 15%씩**으로 채웁니다. 랜덤이 아니라 고정 규칙(채도 높은 순 등간격 추출)이므로 같은 유형이면 항상 같은 팔레트가 나옵니다.

| 진단 유형 | 24색 구성 |
|---|---|
| 봄 브라이트 | 봄 브라이트 17 + 봄 라이트 4 + 봄 웜 3 |
| 여름 뮤트 | 여름 뮤트 17 + 여름 라이트 4 + 여름 쿨 3 |
| 가을 딥 | 가을 딥 17 + 가을 뮤트 4 + 가을 웜 3 |
| 겨울 쿨 | 겨울 쿨 17 + 겨울 브라이트 4 + 겨울 딥 3 |

24 × 0.7 = 16.8, 24 × 0.15 = 3.6이라 정수로 떨어지지 않습니다. 최대잉여법으로 17 / 4 / 3으로 배분했습니다. 팔레트 아래에 구성 내역이 그대로 표시되고, 중복 색은 앞선 유형에 우선 배정한 뒤 제외합니다. 완성된 24색은 색상 순으로 정렬해 띠로 보여줍니다.

## 2-2. TPO 활용 배색

베스트 오브 베스트(★) 1색을 기준으로 **5색 배색**(★ + 보조 4색)을 3가지 만듭니다. 명도차·채도차는 모두 ★색과의 차이입니다.

| 상황 | 색상 관계 | 명도차 | 채도차 |
|---|---|---|---|
| 데일리 | 유사색상 | 3 이상 4 이하 | 3 이하 |
| | | **+ 배색 내 색끼리 명도차 1 이상 (3종 공통)** | |
| 비즈니스 | 유사색상 | 2 이상 3 이하 | 저채도(C 0.5–3.5)만 |
| 이벤트 | 반대색상 | 3 이상 | 3 이상 |

**유사색상** — 먼셀 10색상군 원형에서 동일 색상군 + 양옆 1군 (색상군 거리 ≤ 1). 예: 빨강 ↔ 주황·자주.
**반대색상** — 색상군 거리 4 이상 (최대 5가 정반대). 예: 빨강 ↔ 청록·파랑.

### 선택 순서

1. 조건을 만족하는 색을 **본인 유형 → 같은 시즌 → 776색 전체** 순으로 찾습니다.
2. 색상군이 겹치지 않도록 우선하고, 밝은 쪽 · 어두운 쪽을 번갈아 뽑아 대비를 만듭니다.
3. 4색을 못 채우면 2단계까지 기준을 완화하고, 완화된 색에는 「완화」 표시를 붙입니다.

각 보조 색 옆에 ΔV · ΔC 값이 그대로 표시되므로 규칙이 지켜졌는지 화면에서 바로 확인할 수 있습니다.

### 예외 — ★이 무채색인 경우

★이 회색 계열(N)이면 색상 관계가 정의되지 않습니다. 이때는 채도로 대체합니다 — 유사색상은 채도 4 미만, 반대색상은 채도 8 이상.

### 검증 결과

850개 (유형, ★색) 조합 전부에 대해 배색을 생성해 확인했습니다.

| 상황 | 5색 완성 | 엄격 기준 충족 | 완화 사용 |
|---|---|---|---|
| 데일리 | 850 / 850 | 812 (96%) | 38 (4%) |
| 비즈니스 | 850 / 850 | 848 (100%) | 2 (0%) |
| 이벤트 | 850 / 850 | 848 (100%) | 2 (0%) |

완화 없이 배정된 1,112색을 규칙에 다시 대입해 검사한 결과 **위반 0건**입니다.

데일리에서 완화가 생기는 경우는 ★이 고채도·중명도인데(예: 겨울 쿨 5BG 5.5/10) 명도차 3~4 · 채도차 3 이하를 동시에 만족하는 색이 데이터에 없을 때입니다. 고채도 쿨 색은 명도가 높아지지 않기 때문입니다.

## 2-3. 저장 · 발송

**자동 저장** — [5] 화면의 「결과 카드 만들기」를 누르면 화면 전환과 동시에 진단 자료가 Apps Script `doPost`로 전송되어 `records` 탭에 1행 추가됩니다. 결과 화면에서 「시트에 다시 저장」으로 재전송할 수 있습니다.

**이메일 발송** — 결과 카드를 PNG로 만든 뒤 base64로 Apps Script에 보내고 `MailApp.sendEmail`이 첨부해 발송합니다. 받는 사람은 진단자 정보에 입력한 이메일입니다. 이메일이 비었거나 개인정보 동의가 없으면 버튼이 동작하지 않고 사유를 표시합니다.

| 항목 | 내용 |
|---|---|
| 받는 사람 | 진단자 이메일 (확정) |
| 보내는 계정 | **미정** — 연구소 대표 계정 1개 / 컨설턴트 개인 계정 중 선택 필요 |
| 발송 한도 | 무료 Gmail 하루 100통, Google Workspace 하루 1,500통 |
| 첨부 크기 | 결과 카드 PNG 약 300~600KB (2배 해상도 기준) |

대표 계정 1개로 몰면 컨설턴트가 늘었을 때 하루 100통 한도에 걸릴 수 있습니다. 컨설턴트 수가 10명을 넘어갈 것 같으면 Workspace 계정이나 컨설턴트별 계정 연결을 검토해야 합니다.

## 4. 데이터 구조

원본 `kcolor_data.json`에 3개 필드를 추가한 `kcolor_typed.json`을 만들어 씁니다. 원본은 건드리지 않습니다.

```json
{
  "id": "K-001",  "hue": "2.5R",  "group": "빨강",
  "value": 4.0,   "chroma": 13.0, "ks": "2.5R 4/13",
  "hex": "#D53340","rgb": "213 / 51 / 64", "cmyk": "20 / 92 / 71 / 0",
  "lab": "40.72 / 57.63 / 21.01", "ncs": "1080-R", "pantone": "18-1764",
  "name": "선명한 빨강",

  "tone":   "vv",          ← 추가: 톤코드
  "warmth": -10,           ← 추가: 웜쿨지수
  "temp":   "N",           ← 추가: W / C / N
  "types":  ["SP_BR","WI_BR"]  ← 추가: 배정된 유형 (중성색은 2개)
}
```

유형 코드는 `SP_LT SP_BR SP_WM SU_LT SU_MU SU_CL AU_MU AU_DP AU_WM WI_BR WI_DP WI_CL` 12개. 향후 연구소 자체 체계로 바꿀 때는 `meta.types` 배열의 `ko`/`en` 값만 교체하면 되고, 코드는 그대로 두면 기존 진단 기록과 호환됩니다.

## 5. 교육 모드

같은 앱 안에서 상단 스위치로 전환합니다. 진단 흐름과 완전히 독립적입니다.

- 776색 전체를 대상으로 유형·색상·명도·채도·톤 5축을 자유롭게 조합
- 정렬 기준 전환 (색상순 / 명도순 / 채도순 / 톤순)
- 스와치 클릭 시 먼셀 표기, L\*a\*b\*, NCS, Pantone 대조까지 한 화면

**유형 선택 시 관련 항목 강조** — 유형 칩을 하나 이상 고르면, 그 유형에 실제로 포함된 색상군·명도대·채도대·톤 버튼의 테두리가 금색으로 두꺼워집니다. "봄 브라이트는 어떤 색상·명도·채도·톤으로 이루어지는가"를 필터를 눌러보지 않고도 한눈에 알 수 있습니다.

예시

| 선택한 유형 | 금색으로 표시되는 항목 |
|---|---|
| 봄 브라이트 | 색상 5개(빨강·주황·노랑·연두·초록) / 고명도·중명도 / 고채도 / 선명한 |
| 여름 뮤트 | 중채도·저채도·무채색 / 흐린·탁한·회 |

수업에서 "여름 뮤트에 해당하면서 보라 계열이고 중명도인 색"처럼 조건을 좁혀 가며 보여주기에 적합합니다.

## 5-1. 언어 · 테마 전환

상단에 두 개의 토글이 있습니다.

| 토글 | 동작 |
|---|---|
| KR / EN | 화면 문구, 유형명, 시즌명, 톤 이름, 색상군 이름이 전부 전환됩니다. 색이름은 한글만 있으므로 EN에서는 먼셀 표기를 앞에, 한글 색이름을 뒤에 표시합니다 |
| ☀ / ☾ | 밝은 모드 · 어두운 모드. CSS 변수만 교체하므로 모든 화면에 즉시 반영됩니다. 결과 카드만은 인쇄·발송물이므로 항상 밝은 배경을 유지합니다 |

색상군 영문 표기는 연구소의 색이름 번역 가이드를 그대로 따랐습니다 — 주황 Yellow Red, 연두 Green Yellow, 남색 Purple Blue, 자주 Red Purple.

한 가지 남은 문제는 **색이름 영문 표기**입니다. 776색의 한글 색이름(선명한 빨강, 진한 분홍 …)에 대응하는 영문명이 데이터에 없습니다. 원본 엑셀 `K-color DB v5.xlsx`에는 `Color Name` 열(Lollipop, Dubarry 등 관용색명)이 있지만 이건 계통색명이 아니라 별개 체계입니다. EN 모드에서 색이름을 어떻게 표기할지 결정이 필요합니다.

### 교육 모드

버튼(칩)은 **유형 12 · 색상 계열 8 · 명도 5 · 채도 4 · 톤 14** 그대로 두고, **색상만 40색상환**으로 바꿨습니다. 여러 색상을 동시에 고를 수 있고 다시 누르면 해제됩니다. 가운데 가로 막대는 무채색 16색입니다.

색상환 오른쪽 **색조표**는 두 가지 모드로 자동 전환됩니다.

| 색상 선택 | 색조표 |
|---|---|
| 1개 | 명도 × 채도 **낱칸** 격자 |
| 미선택 · 2개 이상 | **명도 5구간 × 채도 4구간** 밴드 격자 (칸마다 대표색 6개 + 색 수, 누르면 해당 명도·채도 필터) |

**왜 두 모드가 필요한가** — 한 색상 안에서는 (명도, 채도) 조합이 겹치지 않습니다(606색 전수 확인, 중복 0건). 그러나 색상을 합치면 115칸 중 76칸이 2색 이상 겹치고 606색 중 567색(94%)이 겹치는 칸에 들어갑니다. 낱칸으로 그리면 한 칸에 최대 26색이 숨겨지므로, 여러 색상을 볼 때는 구간을 묶어 개수와 대표색을 보여줍니다.

톤을 고르면 색조표에서 해당 톤 구역만 살아나고 나머지는 흐려집니다.

### 배색 내 명도 간격

★색을 포함한 5색 전체에서 **어느 두 색을 골라도 명도차가 1 이상**이 되도록 했습니다. 같은 명도의 색이 나란히 놓이는 일을 막기 위해서입니다.

| 검사 | 결과 |
|---|---|

| 상황 | 보조색 총계 | 엄격 기준 충족 | 5색 미달 |

| 비즈니스 | 3,077 | 2,158 (70%) | 11 |
| 이벤트 | 3,088 | 2,270 (74%) | 0 |

나머지는 명도차 허용 폭을 ±1 넓혀 채웠고, 해당 색에는 「완화」 표시가 붙습니다. 데일리의 완화 비율이 절반을 넘으므로 **데일리의 명도차를 3~4 대신 2~5로 넓히는 편이 나을 수 있습니다.** 결정이 필요합니다.

### v3에서 새로 생긴 문제 — 채도 기준 이원화

새 채도 밴드(C8 / C4 / C0.5)는 **필터 기준**입니다. 그런데 12유형 자동 배정 규칙은 여전히 **C11 / C7 / C3** 경계를 씁니다. 톤경계표의 톤코드도 C11 / C7 / C3 기준입니다.

그래서 이런 어긋남이 생깁니다.

| 예 | 필터에서는 | 유형 배정에서는 |
|---|---|---|
| C 8~10인 웜 색 | 고채도 | 봄 브라이트가 아니라 봄 웜 / 봄 라이트 (C11 미만이므로) |
| C 3.5인 색 | 저채도 | 톤코드는 `dl`/`sf` 계열 (C3 이상이므로) |
| C 0.5~2인 색 | 저채도 | 톤코드는 `gy`/`wh` 계열 (C2 이하 무채 취급) |

**결정이 필요합니다.**

| 선택지 | 결과 |
|---|---|
| A. 필터만 새 기준, 배정·톤은 그대로 | 지금 상태. 톤경계표와 호환되지만 화면상 "고채도인데 브라이트가 아닌 색"이 생김 |
| B. 유형 배정 규칙도 C8 / C4 / C0.5로 통일 | 화면이 일관되지만 12유형 색 수가 전부 바뀌고 톤경계표와 어긋남 |
| C. 톤경계표까지 전부 통일 | 가장 깔끔하지만 기존 톤 체계를 다시 만들어야 함 |

## 8. 미해결 · 확인 필요

- **유형 불균형** — 겨울 딥 159색은 실무에서 너무 많습니다. 유형당 대표색 수를 몇 개로 할지 정해야 합니다.
- **결과 링크의 개인정보** — 링크를 아는 사람은 누구나 진단자 이름을 볼 수 있습니다. 유효기간을 두거나 이름을 가리는 옵션이 필요합니다.
- **AI 이미지** — 아직 미정이라 하셨으니 슬롯만 비워 두었습니다. 실제로 붙일 때 진단자 얼굴을 쓰는 방식이면 별도 동의 항목이 필요합니다.
- **오프라인 사용** — 대면 진단 현장에 인터넷이 불안정할 수 있습니다. 색 데이터는 앱에 내장되어 오프라인에서도 보이지만, 코드 검증과 시트 저장은 인터넷이 필요합니다. 임시 저장 후 나중에 전송하는 방식을 검토할 수 있습니다.
- **이메일 발신 계정** — 연구소 대표 계정 1개로 할지 컨설턴트 개인 계정으로 할지 미정입니다. 대표 계정이면 무료 Gmail 하루 100통 한도가 병목이 됩니다.
- **인종 항목의 취급** — 민감 정보에 해당할 수 있어 필수로 두지 않았습니다. 수집 목적을 개인정보 동의문에 명시하는 편이 안전합니다.
- **L\*a\*b\* 측정 조건** — 색채계 기종·조명·측정 각도에 따라 값이 달라집니다. 앱은 계산만 하고 해석하지 않습니다. 기록 신뢰도를 위해 측정 기기명과 조건을 함께 남기는 항목을 추가할지 결정이 필요합니다.
- **TPO 배색의 보조 색 출처** — 조건이 엄격해 본인 유형 안에서 4색을 못 채우면 같은 시즌, 그래도 부족하면 776색 전체에서 가져옵니다. 그래서 유형 팔레트 밖의 색이 배색에 섞일 수 있습니다. 예를 들어 가을 딥의 이벤트 배색에 청록·파랑 고명도 색이 들어옵니다 — 반대색상 규칙상 당연한 결과지만 "가을 딥이 입을 색"인지는 별개 문제입니다. 배색 후보를 본인 유형으로만 제한할지, 지금처럼 열어둘지 결정이 필요합니다.
- **배색 결과 수동 교체** — 자동 생성된 보조 색을 컨설턴트가 손으로 바꿀 수 있게 할지 정해야 합니다.
- **채도 기준 이원화** — 7-1장 참조. 필터(C8/C4/C0.5)와 유형 배정·톤코드(C11/C7/C3)가 다릅니다. A·B·C 중 선택이 필요합니다.
- **팬톤 컬러명 중복** — v6에서 Pantone=x 색 170개를 제외하면서 해소됐습니다.
- **영문 계통색명** — 팬톤명은 관용색명이지 계통색명이 아닙니다. EN 모드에서 "Vivid Red" 같은 계통색명이 필요하면 별도로 만들어야 합니다.
- **에듀케이터의 기록** — 교육 모드에는 저장할 진단 기록이 없습니다. 사용 시간이나 접속 로그를 남길지, 남긴다면 요금 산정에 쓸지 정해야 합니다.
